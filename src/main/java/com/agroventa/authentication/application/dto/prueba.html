1. Visión General de la Arquitectura
Sección 01

AgroVenta está compuesta por una aplicación móvil nativa Android y un backend de microservicios reactivos desplegados en Amazon Web Services (AWS). La arquitectura sigue el patrón Hexagonal (Ports & Adapters) en el backend y una comunicación REST con JWT.

2. Microservicios y Responsabilidades
Sección 02
🔐
auth-service
Registro, login, recuperación de contraseña con código 6 dígitos, emisión de JWT HS256. Base de datos: auth_db.
🌿
products-service
Catálogo, publicación de cosechas, órdenes de compra, pagos Wompi, gestión de despachos por camión. Base de datos: products_db.
📧
notifications-lambda
Consume eventos de SQS y envía correos transaccionales vía AWS SES: bienvenida, código de reset, confirmación de pago, despacho.
🧾
billing-lambda
Genera PDF de factura electrónica con PDFKit, almacena en S3 y notifica al comprador con el link de descarga.

S3Bucket público para imágenes de productos. Bucket privado para facturas PDF (SSE-S3).modules/s3
Secrets ManagerAlmacena JWT secret, contraseñas de BD, keys de Wompi. Nunca en variables de entorno en texto plano.modules/secrets
IAM (OIDC)Roles para ECS Tasks, Lambda y GitHub Actions (sin credenciales estáticas).modules/iam
AWS SESEnvío de correos transaccionales desde la Lambda de notificaciones.Configuración manual
CloudWatchLogs de ECS tasks y API Gateway. Retention: 7 días.Incluido en ECS/API GW
💡 Decisión: ECS Fargate vs EKS. Se elige ECS Fargate porque con créditos de estudiante AWS no cobra el control plane (EKS cobra ~$72/mes solo por el cluster). ECS Fargate cubre el 100% del caso de uso con menor complejidad operacional.

Requests autenticados

⚠ Regla de despacho por camión: El agricultor define un volumen mínimo de carga (ej. 300 kg). Los pedidos se acumulan hasta alcanzar ese mínimo. Solo cuando se completa la carga del camión el agricultor puede confirmar el despacho en bloque, garantizando viabilidad logística y reduciendo costos de flete.

6. Pipeline CI/CD (GitHub Actions)
Sección 06
✅
Fase 1 — Test
mvn test con PostgreSQL en contenedor. Tests unitarios + integración. Fallo bloquea el pipeline.
🐳
Fase 2 — Build Docker
mvn package -DskipTests. Docker build → push a ECR con tag SHA + latest.
🏗
Fase 3 — Terraform
terraform plan (PR) / terraform apply (main). Infra como código versionado.
🌐
Fase 4 — Deploy ECS
aws ecs update-service --force-new-deployment. Rolling update sin downtime.
Autenticación OIDC: GitHub Actions usa OIDC (sin credenciales AWS estáticas) para asumir un rol IAM temporal con permisos mínimos: push a ECR + force-deploy en ECS.
